## Security and resilience boundaries

- `src/lib/api.test.ts`: HTTPS origin/path allowlist, bounded JSON responses, invalid content, timeout, cache, retry and independent cancellation.
- `src/lib/pokemon-catalog.test.ts`: GraphQL catalog validation and request behavior.
- `src/lib/pokemon-3d.test.ts` and `src/lib/pokemon-3d.transport.test.ts`: model asset allowlist, shared transport, cancellation, timeout, expiring cache, retry, and omitted credentials.
- `src/lib/storage.test.ts`, `src/lib/team-storage.test.ts`, `src/lib/team-transfer.test.ts`: malformed values, unavailable storage, runtime validation and import limits.
- `src/theme-init.test.ts`: validated persisted theme, default theme and denied storage before React mounts.
- `e2e/recovery-security.spec.ts`: browser-level corrupt storage recovery, unknown resource rejection without API requests, and external markup rendered as inert text.
- `e2e/team-transfer.spec.ts`: real browser download/upload, regenerated team IDs, reload persistence, malformed/invalid/oversized import rejection without changing existing teams.
- `src/config/csp.test.ts`: production connection policy excludes localhost. Playwright uses Vite's development CSP; it does not validate deployed HTTP headers or production CSP enforcement.

## Verification

Run `npm run check` for formatting, lint, Vitest with coverage thresholds, the complete Chromium Playwright suite, TypeScript and the production build. Current configured minimums are 85% statements, 77% branches, 85% functions and 88% lines. The HTML coverage report is generated at `coverage/index.html`.

E2E API journeys use deterministic fixtures instead of live PokéAPI responses. Map image hosts are blocked in map tests so catalog and interaction checks do not depend on remote tiles. These tests do not establish live-service availability, full battle parity, cross-browser compatibility, dependency vulnerability status, or absolute application security. Battle parity limitations are tracked separately in the battle audit documents.
